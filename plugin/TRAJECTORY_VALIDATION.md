# Проверка фактической 5D-траектории

Реализовано 25 октября 2026 года. Это минимальный проверяющий контур после нарезки,
а не разрешение на физический запуск принтера.

## Как запускается

`slice` в режимах Spiral/Spiral Full автоматически проверяет G-code активного стола.
Отдельный инструмент `validate_5d_trajectory` повторяет проверку без новой нарезки.
`get_slice_result` возвращает актуальный отчёт либо `not_checked`, если исходные данные
изменились. В карточке результата показаны отдельные проверки и номера проблемных строк.

Экспорт повторно использует только отчёт, соответствующий текущим G-code, столу,
геометрии, матрицам, пресетам, входному контракту и исходному applied STL. При `fail`
экспорт блокируется. При `unknown` допустим экспорт для анализа; рядом сохраняется
`result.gcode.validation.json`. Недоступность worker блокирует экспорт с явной ошибкой.
Хеш отчёта относится к точным проверенным байтам; отдельный хеш сохраняется для
экспортированного файла с комментариями штатного writer.

## Что проверяется

- Все G0/G1, в том числе холостые и модальные блоки. G90/G91, M82/M83,
  G54/G55/G56, переобозначение координат G92 и развёрнутые A/C учитываются явно.
- Положения осей на концах каждого линейного участка по явно заданным пределам.
  Для линейной интерполяции это покрывает весь диапазон каждой оси на участке.
- Командуемая подача и скорости отдельных осей, когда контракт явно определяет
  время перемещения через линейную XYZ-подачу. Чисто угловые ходы без закона подачи
  остаются неизвестными.
- Прямая кинематика `table_AC` из существующего `toolpath_physics`, с ограниченным
  бюджетом адаптивного разбиения. Условный `analysis_assumption` не получает статус
  калиброванной кинематики.
- Непрерывное движение набора сфер оболочки головы относительно неподвижных сфер,
  капсул и AABB в машинной системе. Проверяется минимальный зазор по всему отрезку,
  а не только его концам. Используются только явно переданные размеры.
- Для актуального applied plan при наличии pose-контракта и диаметра материала
  вызывается прежний `deposition`: объёмы, длины и направления укладки, без замены его формул.

## Данные машины

В настройках плагина укажите путь в поле «JSON измерений, нагрузок и 5D-проверки».
Существующий файл может дополнительно содержать объект:

```json
{
  "trajectory_validation": {
    "machine_contract": {},
    "pose_contract": {},
    "collision_geometry": {}
  }
}
```

Каждый из трёх объектов необязателен. Пустой или отсутствующий объект не считается
подтверждением: отчёт перечисляет недостающие данные. Поля контрактов:

| Объект | Поля |
|---|---|
| `machine_contract` | `source`; `initial_state` с `axes={X,Y,Z,A,C}`, `coordinate_system`, `units`, `absolute`, `extrusion_absolute`, `e`, `feed_mm_min`; `axis_limits={ось:[min,max]}`; `axis_limits_frame="machine"` либо `"work"` с `axis_limits_coordinate_system`; `max_feed_mm_min`; `max_axis_speed_per_min`; `feed_mode="linear_xyz_mm_per_min"`; `rapid_uses_feed` |
| `pose_contract` | `type="table_AC"`, `angle_unit="degree"`, `source="analysis_assumption"` либо `"machine_calibration"`, `interpolation="linear_unwrapped_joints"`, `table_pivot_mm`, `nozzle_axis_machine`, `work_offsets={G54:4x4,G55:4x4,G56:4x4}`; для G92 A/C — `rotary_g92="preserve_physical_angle_global"` |
| `collision_geometry` | `frame="machine"`, `clearance_mm`, непустые `tool_spheres` и `obstacles`. Сфера головы: `center_mm` — фиксированное смещение от TCP, `radius_mm`. Препятствия: `type="sphere"` с `center_mm/radius_mm`, `"capsule"` с `start_mm/end_mm/radius_mm`, `"aabb"` с `min_mm/max_mm` |

Начальное состояние задаётся для входа в программу, а не произвольно для первого
напечатанного слоя. Рабочие смещения должны соответствовать контроллеру. Пределы XYZ
нельзя подменять размером области печати. Номинальные значения активного пресета
записываются как наблюдения профиля, но автоматически не объявляются калибровкой.
Пример с искусственными размерами есть в `plugin/tests/test_trajectory_validation.py`;
этот пример не является профилем реального Hybrid 530.

## Границы минимальной версии

`START`, `END`, homing, смена инструмента и неизвестные команды не раскрываются
автоматически. После них состояние может быть неизвестно; соответствующая часть
траектории не получает `pass`. Отчёт различает диапазоны буквальных команд и
восстановленные физические положения. Бюджет поз/коллизий ограничен; его исчерпание
не останавливает чтение оставшихся команд и отмечается в покрытии.

Не проверяются ускорение/рывок, torque и сглаживание контроллера, движущаяся оправка,
постепенно напечатанный объём и полная геометрия машины. Статический геометрический
`pass` относится только к переданным оболочкам. Поэтому общий статус полной проверки
остаётся `unknown` при отсутствии нарушений, а `physical_print_approval=false`.
Область анализа явно сохранена в каждом отчёте.

## Воспроизводимые проверки

```powershell
.\.venv-functional\Scripts\python.exe -m pytest plugin/tests/test_trajectory_validation.py plugin/tests/test_trajectory_collision.py plugin/shell_tests/test_trajectory_bridge.py plugin/shell_tests/test_trajectory_worker.py -q
```

Сохранённый файл можно проверить тем же worker без запуска GUI:

```powershell
.\.venv-functional\Scripts\python.exe plugin/tools/validate_5d_gcode.py result.gcode --inputs machine_inputs.json --output validation.json
```

Без `--inputs` возвращаются доступные сведения о командах/покрытии и явные пропуски,
поддерживается также `.gcode.gz`. Код выхода 1 означает найденное нарушение, 0 —
отсутствие найденных нарушений в проверенной области; `unknown` остаётся в самом отчёте.

Нативная проверка использует отдельный профиль STE и команду runtime
`trajectory_check` с `output_dir`: Qt → реестр инструментов → modern worker → штатный
GCodeWriter. В ней искусственные превышение A и столкновение блокируют экспорт,
а файл для анализа получает отчёт. Сцена пользователя и физический принтер не затрагиваются.

Проверка этой реализации: 489 тестов ядра и оболочки прошли, один пропущен;
43 проверки новых геометрических модулей прошли во встроенном Python 3.5.7 STE.
Нативный тест подтвердил полный маршрут Qt → worker → блокировка/разрешение экспорта
и сохранение sidecar. Сохранённый реальный `case_02_cylindrical_090` обработан целиком:
750 885 строк, 750 096 перемещений, около 17 секунд. START/END и отсутствующие данные
машины корректно оставили физические проверки неизвестными.
Локальные диагностические файлы: `.runtime/trajectory_mvp/001_trajectory_check.json`,
`.runtime/trajectory_mvp/native_default.json`, `.runtime/trajectory_mvp/embedded/all_contracts.json`.
