# Передача для интеграции с оболочкой плагина

Обновлено после слияния Lenaz в main 24.10.2026. Оболочка теперь подключена к
исходному ядру через современный worker и `runtime_adapter` в Qt.
Установка, инструменты и ограничения: [AIAssistant/README.md](../AIAssistant/README.md).
Приведённый ниже исследовательский FE/5D протокол сохраняет свои ограничения.

## Готово

- `planner.plan_case(...)` и Qwen/Timeweb извлекают требования и строят предложение.
  LLM не придумывает измеренные константы и не разрешает печать.
- `functional_analysis` — предварительная оценка; `applied=false` до реальных слайсов.
- `STEPlannerRuntime` выполняет apply/readback/slice/export/undo/redo в Qt.
  Экспериментальные 5D операции доступны только в отдельном `analysis_only` профиле.
- На семи исходных деталях получены 20 нативных слайсов: 14 classic, 4 Spiral,
  2 Full. Наклон 90° крыльчатки имеет открытый `model_height_coverage=fail`.
- Исправлена порча индексированной 5D-сетки в CLIParserBackend: последовательные
  индексы сохраняют каждый исходный треугольник. Старый fallback исключён и сохранён
  отдельно в `representation_regression`; исходные STL не менялись.
- `toolpath_physics`: дорожки, кинематика, ортотропия 9 констант, символические
  материальные операторы, условный FE, чувствительность к ковариации свойств.
- `elasticity`: T4/T10, силы и моменты, проверка равновесия/энергии.
- `sliced_search`: отдельный native callback для каждого кандидата, привязка по SHA.

## Границы потоков и процессов

1. Оболочка хранит пользовательский проект, выбранный STL и текст ТЗ.
2. Qwen/ядро и тяжёлый Gmsh/SciPy расчёт выполняются современным worker-процессом.
   Во встроенную Python 3.5 среду STE новые библиотеки не устанавливаются.
3. Изменения сцены, контейнеров, выбор backend и Undo/Redo — только в Qt-потоке.
   Используйте существующий `runtime_adapter.create_operation`, не дублируйте
   запись настроек из UI или LLM.
4. Для каждого кандидата нужен самостоятельный native slice. Изменение ориентации,
   режима или профиля инвалидирует старые дороги и результаты физики.
5. После slice worker получает decision, applied, sliced, G-code и опциональные
   измерения/нагрузки; вызывает `toolpath_physics.analyze_slice`.
6. Возврат JSON в оболочку через процессный канал/локальные атомарные файлы.
   MCP/чатовый transport и визуальная оболочка реализованы в `AIAssistant/`.

## Контракт задачи оболочки

Минимальный запрос worker:

```json
{
  "request_id": "application-owned-uuid",
  "mesh_path": "absolute/local/part.stl",
  "geometry_sha256": "sha256-of-source-bytes",
  "task_text": "Требования пользователя",
  "mode": "classic",
  "analysis_only": true,
  "functional_spec": null,
  "noise_spec": null
}
```

Это исследовательский контракт FE/5D. Обычный HTTP/MCP `plan_print` реализован
с application-owned request_id, SHA, процессным worker, отменой и Qt apply/readback;
параметр `analysis_only` не доступен LLM и не обходит ограничения обычного проекта.
Перед применением сверяйте request_id, актуальный SHA и decision текущего проекта.
Пути должны принадлежать выбранной пользователем рабочей области. Ключ Timeweb
остаётся в окружении worker/.env; не кладите его в JSON, 3MF или логи UI.

Выход расчётных функций — `Result.to_dict()`:
`value,unit,status,evidence,uncertainty,domain,trace,model_id,model_class`.
Отображайте исходные единицы и ограничения рядом с метриками.

| Статус | Поведение оболочки |
|---|---|
| `computed` | Показать вычисление в пределах указанной модели; это не квалификация печати |
| `needs_input` | Показать конкретные missing из trace, сохранить предложение |
| `needs_calibration` | Показать условные метрики, запросить измерения/протокол; не обещать прочность |
| `needs_resolution` | Предложить явный бюджет/уточнение сетки, не подменять данные |
| `needs_slice_verification` | Показать failed проверки и проблемную ориентацию |
| `analysis_pending` | Расчёт был остановлен; показать native slice отдельно и кнопку продолжения |
| `invalid_input`, `out_of_domain`, `infeasible` | Не применять результат; показать причину |

События UI: `intake`, `planning`, `awaiting_slice`, `slicing`, `physics`, `done`,
`cancelled`, `error`. Добавить отмену worker; поздний ответ старого request_id
не должен менять новый проект. Прогресс без общего ETA; Windows Job Object launcher
ограничивает только дочерние движки своего изолированного запуска.

## Что доделать первым

1. UI/worker/Qt-operation подключены; тесты устаревшего ответа, отмены, readback
   и единого Undo/Redo добавлены. Дальнейший этап: UI для native FE-поиска с
   повторной нарезкой каждого кандидата и измеренными физическими входами.
2. Повторить оценку Full по актуальным G-code с новым контрактом сброса угла.
   Для Full новый контракт `rotary_g92=preserve_physical_angle_global` умеет
   отслеживать A/C G92; последние сохранённые Full-сводки могут ещё требовать
   повторного запуска с этим контрактом. XYZ G92 пока требует отдельной модели.
3. Повторить field-анализ колеса: `python experiments/summarize_real_toolpath_physics.py
   --case 2 --mode cylindrical --phase 0 --field-case 2 --background-field`.
   Это фоновая интеграционная сетка, не разрешённая геометрия валиков.
4. Получить проверенную кинематику машины, эксплуатационные закрепления/нагрузки,
   road/interface свойства и их неопределённость. Сейчас абсолютная физическая
   жёсткость и оптимум не подтверждены.
5. Уточнить finite-bead/пористость/перекрытия и сходимость; для TPU/сильфона нужны
   нелинейность и контакт. Тепловая история, центробежные массовые силы, усталость
   и износ в этом FE интерфейсе не реализованы.
