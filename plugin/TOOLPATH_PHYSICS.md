# Физика после реального слайсинга STE

Кандидат (исходный STL, ориентация, режим, профиль) → отдельный нативный STE-слайс
→ проверка readback/байтов/геометрического preprocessing → G-code → кинематика
в системе детали → локальные оси дорожек → неоднородное материальное поле →
эксплуатационные нагрузки и закрепления → FE → сравнение и устойчивость.

Этот блок остаётся отдельным исследовательским worker API/CLI. Чат Lenaz уже
выполняет планирование, apply/readback, нарезку и экспорт, но не запускает
автоматически весь FE-поиск. Исправление передачи исходного STL по ID и будущий
промпт выбора пресетов не меняют приведённые ниже формулы и условия квалификации.

Строгий вывод, девять констант, энергетические преобразования, моментные нагрузки,
границы аппроксимаций и статьи 2025–2026:
[математика и первичные источники](../data/research/07_toolpath_physics_math.md).

## Реализованные интерфейсы

- `toolpath_physics.deposition(text, decision, diameter, pose_contract=None)`:
  дорожки в исходной системе STL, локальные базисы Q, номинальные объёмы E с
  погашением ретракции. Только C/A движения сохраняются. Полные обороты не
  сворачиваются. `retain_roads=False` вычисляет сводку потоком для крупных моделей.
- `material_field(volume_mesh, roads, road_elastic=None)`:
  точное пересечение центральных отрезков с тетраэдрами, однократное распределение
  объёма на общих гранях, девять символических операторов Dₑ без угадывания E/G.
  Это coarse line-volume модель, **не** конечные Boolean-валики. Сообщаются пустоты,
  переполнение ячеек, потеря объёма и необходимость пространственной сходимости.
- `analyze_slice(path, decision, applied, sliced, diameter, ...)`:
  проверка происхождения; `.gcode` или `.gcode.gz`, хэш исходных распакованных байтов.
  Опциональны `pose_contract`, `volume_mesh`, `measured_material`, `load_cases`,
  `fixed`, `service_conditions`. Неизвестные константы и допустимые не заполняются.
- `sliced_search.evaluate_candidates(candidates, native_slice, analysis_inputs)`:
  вызывает STE-worker отдельно для каждого кандидата, проверяет привязку physics
  к этому decision. Текущая coarse-модель не выбирает подтверждённый физический
  оптимум: unresolved calibration/convergence остаются явными.
- `compliance_sensitivity(mesh, operators, displacement, covariance_MPa2=None)`:
  производные податливости по девяти коэффициентам D и линейное распространение
  явно заданной ковариации. Вызывается также после условного coarse-FE расчёта.
  Распределение шума не назначается; при смене контакта/топологии слайса эта
  локальная оценка не доказывает устойчивость.
- `elasticity.solve(..., material_frames=Q)` принимает полную ортотропию;
  `element_stiffness=D_e` — неоднородные глобальные SPD матрицы без искусственного
  заполнения пустот. Для такого поля запас прочности дорожек не вычисляется из
  среднего напряжения элемента. `moment_Nmm` задаёт результирующий момент
  относительно `reference_point_mm` либо взвешенного центра выбранной области.

## Поля напряжений и давления

`elasticity.solve` возвращает полный симметричный тензор Коши в исходных координатах
детали (`element_stress_tensor_MPa`), главные напряжения и диагностическое напряжение
Мизеса. `element_pressure_MPa = -tr(σ)/3` — среднее объёмное давление; положительный
знак означает сжатие. Это отдельная величина: при одноосном сжатии торца давлением
10 МПа объёмное давление равно 10/3 МПа, а давление на торце — 10 МПа.

На граничных гранях сохраняются `boundary_traction_MPa = σn`,
`boundary_pressure_MPa = -nᵀσn` и модуль касательной тяги
`boundary_shear_traction_MPa`. Внешние нормали, центры и площади находятся в
`boundary_normals`, `boundary_centers_mm`, `boundary_areas_mm2`; порядок совпадает
с `boundary_faces`. Это напряжения на поверхности заданной линейной FE-задачи,
**не решение неизвестного контактного давления между двумя деталями**.

Поля элементов вычисляются в центрах без узлового сглаживания. Отдельно хранятся
`element_pressure_range_MPa` и `element_von_mises_max_MPa`: экстремумы по вершинам
не заменяются усреднённым значением. Для прямолинейного T10 напряжение аффинно;
давление на грани берётся из точного тензора в центре грани, а не из центра элемента.
`field_semantics` фиксирует эти соглашения. Мизес не заменяет направленный критерий
разрушения печатного материала и не используется для подтверждения прочности дорожек.

Нагрузка может задаваться постоянным давлением по внешней нормали выбранных граней:

```json
{"id": "compression", "on": {"axis": 0, "value_mm": 10}, "pressure_MPa": 10}
```

Единицы — МПа = Н/мм². Давление положительно внутрь детали; отрицательное задаёт
растягивающую нормальную тягу. `pressure_MPa` исключает `force_N`/`moment_Nmm`
в одном сценарии. На каждой выбранной грани интегрируется `t = -p n` с согласованными
силами T3/T6; реакции проверяются вместе с равновесием и энергией.
Давление может охватывать замкнутую поверхность и пересекать закрепления:
силы на закреплённых степенях свободы сохраняются в реакции `Ku-f`.
Условия закрепления и геометрия пятна нагрузки задаются инженером. Контакт,
давление расплава, большие деформации и усталость этим интерфейсом не рассчитываются.

Точные программные проверки: [test_pressure_fields.py](tests/test_pressure_fields.py).
Проверка сохранённых реальных 5D-слайсов:

```powershell
python experiments/check_pressure_physics.py --output .runtime/pressure_audit.json
```

Отчёт и ограничения: [pressure_validation](../experiments/pressure_validation/README.md).
Чат не запускает этот FE-блок автоматически; новые карты доступны в worker API/CLI.
Без измеренных свойств и кинематики появление полей в API не означает появления
достоверной карты конкретной отпечатанной детали.

Для `measured_material` обязательны `source=physical_test`, `protocol`,
`constitutive_scale=printed_road`, контекст станок/материал/режим, все
`functional.PROCESS_KEYS` в `settings`, совпадающие эксплуатационные условия в
`service_conditions={temperature_C,environment,load_regime}` и `elastic`.
Эффективные свойства образца с заполнением нельзя повторно масштабировать долей
материала. Достоверность объявленного измерения проверяется вне программы.

Полная ортотропия:
`elastic={E1_MPa,E2_MPa,E3_MPa,nu12,nu13,nu23,G12_MPa,G23_MPa,G13_MPa}`.
Проверяется SPD compliance с взаимными коэффициентами Пуассона.

## 5D и машинный контракт

Без явного отображения позы 5D возвращает `needs_input`. Поддержан идеальный
`table_AC` с `R=Rx(A)Rz(C)`, `angle_unit=degree`,
`interpolation=linear_unwrapped_joints`, `table_pivot_mm`,
`nozzle_axis_machine`, `work_offsets={G54:4x4,G55:4x4,G56:4x4}`.
Для сохранения физического угла при G92 A/C требуется явный контракт
`rotary_g92=preserve_physical_angle_global`. Пространственный G92 XYZ пока
требует отдельного отображения; сбросы не игнорируются.
Источник — `analysis_assumption` или `machine_calibration`. Сводки с первым
источником условны; это не проверка реальной кинематики и коллизий станка.
G92 пространственных осей, firmware-retraction и нестандартный flow требуют
расширения состояния контроллера. START/END отмечаются как непрозрачные макросы.

Режим `analysis_only` разрешён только в отдельном профиле runtime и не означает
разрешения печати. Рабочий GUI-адаптер сохраняет прежние ограничения 5D.
Ошибка Boolean в штатном backend не должна маскироваться его fallback-геометрией:
runtime фиксирует её и отказывает в зачёте результата.
Для STE 7.10 адаптер также сохраняет треугольники при двойном применении индексов
в CLIParserBackend: 5D-модели передаются как sequential indexed triangle soup.
Оригинальная геометрия и координаты не меняются; регрессионный тест проверяет
результат обеих операций штатного backend.

## Воспроизведение на семи исходных деталях

Из корня репозитория, современный worker с Gmsh/SciPy и установленным STE 7.10:

```powershell
python experiments/check_real_toolpath_physics.py
python experiments/summarize_real_toolpath_physics.py --skip-existing
python experiments/summarize_real_toolpath_physics.py --case 2 --mode cylindrical --phase 0 --field-case 2
python experiments/summarize_real_toolpath_physics.py --case 2 --mode cylindrical --phase 0 --field-case 2 --background-field
```

Сохраняются исходные STL/TЗ и их хэши, две независимые ориентации каждого 3D
кандидата, допустимые маршруты 5D, нативные readback, 3MF и сжатые без потери
G-code. Для 3D 90° — наклон вокруг X, меняющий нормаль слоёв; для 5D — фаза вокруг
сохранённой оси оправки. Произвольная новая ось оснастки не выдумывается.
Каждый слайс содержит один образец; это явно не проверка исходной партии целиком.
Таймауты и отказы маршрутов остаются в manifest/отчёте.

`--background-field` явно выбирает фоновую сетку интегрирования дорожек вместо
сплошной сетки STL. Box не заполняется материалом: пустые ячейки остаются пустыми.
Это обход зависимости интегрирования от дефектов поверхности, а не исправление
исходной геометрии или доказательство точности расчёта пористости.

Анализ одного сохранённого кандидата:

```powershell
python plugin/tools/analyze_sliced_physics.py experiments/real_toolpath_physics/case_02_cylindrical_000 --diameter 1.75 --output physics.json
```

Без измеренной кинематики 5D этот вызов правильно вернёт `needs_input`.
`--inputs` принимает JSON перечисленных выше опциональных входов.

## Что нельзя утверждать по результатам

Реальный STL, успешная нарезка и номинальный расход не измеряют прочность,
пористость, сцепление, коробление или усталость. Линейная статика не подтверждает
большие деформации сильфона/TPU, контакт, износ и центробежные режимы. Эти
ограничения описаны в математическом документе. Отсутствие калибровки означает
`needs_calibration`, а не физически подтверждённый оптимум.
