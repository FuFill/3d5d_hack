# Функциональная ориентация и механические карты

`planner.plan_case(..., functional_spec=...)` подключает поиск ориентации и
параметров по заданным нагрузкам и измеренным профилям напечатанного материала.
Без этого входа старые решения и patch сохраняются; `functional_analysis`
объясняет, каких данных не хватает.

Математика: [05_functional_orientation_math.md](../data/research/05_functional_orientation_math.md).

## Поток и ответственность

Назначение/поверхности → базовый материал и профиль → объёмная сетка →
анизотропная статика → ориентации × процессные профили → жёсткие ограничения →
уточнённая сетка → patch и запросы поддержек.

- `volume_mesh.py`: Gmsh, замкнутый однокомпонентный STL, T4/T10, сохранение
  объёма и ограничение размера задачи. Отверстия не заполняются произвольным
  Delaunay; для отдельных тел нужна контактная модель.
- `elasticity.py`: SciPy sparse, линейная трансверсально-изотропная упругость.
  T10: 4-точечная квадратура, максимумы FI на вершинах элемента, где достигается
  максимум выпуклого критерия для аффинного напряжения; не только точки Гаусса.
- `functional.py`: геометрические и полученные из напряжений направления,
  поворот вокруг вертикали и кольцо ±10°. Конечный поиск, не глобальный оптимум.
  Сохраняются общая податливость, перемещения и запас; FI/перемещения блоков;
  средняя/максимальная ступенчатость и возможный контакт важных областей.
- `assistant.py`: LLM извлекает факты с цитатами. Валидатор проверяет роли,
  единицы/направления; максимум одна попытка исправления. Модель не задаёт
  упругость, прочность, сетку, настройки или статусы проверок.
- `planner.py`: обновляет patch, трансформацию, размещение партии и контекст
  Double ML после применимой оценки. Симуляция не повышается до квалификации.

## Входные данные

Полный **программный** пример: [beam_spec.json](../experiments/functional_artifacts/beam_spec.json).
Его `source=software_fixture`: это не справочник свойств материала. Объёмные сетки
строятся через `--mesh-size`; большие воспроизводимые field-dump JSON остаются
локальными, в Git хранятся рецепт, метрики и изображения.

| Поле | Содержание |
|---|---|
| `purpose` | Назначение |
| `geometry_sha256` | SHA-256 STL; фиксирует нумерацию поверхностных граней |
| `volume_mesh` | `nodes_mm`, `elements`, `geometry_sha256`; T4 или прямолинейный T10 в порядке Gmsh |
| `convergence_mesh` | Более мелкая сетка той же детали; обязательна для включения рекомендации в основной план |
| `service_conditions` | `temperature_C`, `environment`, `load_regime="static"`; должны совпадать с профилями и ТЗ |
| `fixed` | `{on:selector, dofs:[0,1,2]}` — эксплуатационные закрепления |
| `load_cases` | `{id,on:selector,force_N:[Fx,Fy,Fz]}` — полная сила равномерной поверхностной тяги |
| `profiles`, `baseline_profile_id` | До 8 профилей; исходный совпадает с эффективными настройками базового плана |
| `limits` | `safety_factor>=1`, `max_displacement_mm>0`; необязательный `max_staircase_mm` |
| `surface_regions` | `{id,face_ids,importance,forbid_support_contact}` — грани исходного STL |
| `blocks` | Непересекающиеся `{id,bounds_mm:[min,max]}`; элементы относятся к блоку по центроиду |

`selector`: плоскость `{axis:0|1|2,value_mm,tolerance_mm}` или
`{bounds_mm:[[xmin,ymin,zmin],[xmax,ymax,zmax]]}`. Нагрузки действуют на полные
граничные грани, не на ближайшую вершину. Для T10 используется согласованная
поверхностная тяга. Удаляемые поддержки печати не входят в `fixed`.

Каждый профиль содержит `id`, `source="physical_test"`, `protocol`,
`context={machine_id,material_id,printing_mode}`, точные `service_conditions` и:

- `settings`: все `functional.PROCESS_KEYS`, нативные единицы STE. Заполнение 60
  означает 60%, не 0.6. Неизменённые отключённые настройки не записываются;
- `elastic={E_xy_MPa,E_z_MPa,nu_xy,nu_xz,G_xz_MPa}` — эффективные свойства
  напечатанной структуры именно для этого процесса;
- `strength={tensile_xy_MPa,compressive_xy_MPa,tensile_z_MPa,compressive_z_MPa,
  shear_xy_MPa,shear_xz_MPa}` — обоснованные допускаемые значения.

`software_fixture` допускает демонстрацию и карты, но основной проект не меняет.
Паспорт полимера не заменяет калибровку заполненной структуры. Подлинность
заявленных физических измерений программа сама удостоверить не может.

Гомогенизация однородна для каждого профиля. Локальные модификаторы заполнения
по блокам пока не моделируются: для них нужна неоднородная материальная модель.
Настройки выбираются внутри таблицы профилей, а не произвольно за её пределами.

## Метрики и ограничения

| Метрика | Смысл |
|---|---|
| `effective_stiffness_N_per_mm` | F²/(fᵀu), эффективная жёсткость при одной полной силе |
| `compliance_Nmm` | fᵀu, меньше — жёстче при той же нагрузке |
| `max_displacement_mm` | Максимум по узлам FE-модели |
| `safety_factor_min` | 1/max FI по вершинам элементов и направлениям для случая нагрузки |
| `blocks[].compliance_contribution_Nmm` | Вклад блока в податливость; вклады складываются в общую |
| `blocks[].energy_share` | Доля энергии деформации блока |
| `staircase_mean_mm`, `staircase_max_mm` | Геометрическая ступенчатость, **не Ra** |
| `Ra_um`, `flatness_mm` | `null`: измеренной модели микрорельефа/термокоробления нет |

Инверсию локального вклада энергии нельзя называть независимой жёсткостью блока:
для неё пришлось бы отдельно задать связи блока с соседями. Карты сохраняют
координаты/границы объёмной сетки, перемещения, энергию, FI и направления главного
растяжения. Отрисовка не сглаживает максимумы проверок.

Сходимость: изменение C и максимума перемещений ≤5%, FI ≤10%, плюс ограничения
на уточнённой сетке относительно **также уточнённого** исходного решения.
Это численная проверка, а не физическая квалификация. Сингулярности возле острых
зажимов нельзя устранять удалением максимума из метрики.

## Поддержки и 5D

Для Classic выдаются маски и закрытые призмы с ключами STE `support_mesh`,
`support_mesh_drop_down`, `anti_overhang_mesh`, сериализованные как
`add_modifier_mesh` с привязкой к модели. Запрещённый контакт отклоняет кандидат.
Слайсерный адаптер должен исполнить операции, прочитать настройки и проверить
G-code. Реализован и проверен адаптер установленного STE 7.10.12:
[RUNTIME.md](RUNTIME.md). Сама призма остаётся запросом; подтверждение контакта
сохраняется отдельно по реальным траекториям контролируемой поверхности.

Spiral/Full используют радиальные нормали и отдельный сердечник Full.
Перебираются сторона крепления и четыре фазы вокруг выбранной существующим
ядром оси; произвольная оснастка не изобретается. Эксцентричные детали
центрируются по оси оправки, а не bounding box. Без головки/оснастки/траектории
результат остаётся `needs_input` и не включается в основной patch.

## Запуск

Используйте отдельный современный worker. Новые бинарные Gmsh/SciPy не
устанавливаются во встроенный Python 3.5. Исходники ядра сохраняют грамматику
3.5, можно передать готовую сетку. Адаптер запускается во встроенном Windows
Python 3.5; расчёт объёмной механики выполняется современным worker.

```bash
python -m venv .venv-functional
.venv-functional/bin/python -m pip install -r experiments/functional_requirements.lock.txt
export STE_RESOURCES_DIR=/path/to/STE-Slicer/resources
.venv-functional/bin/python experiments/check_functional_integration.py
.venv-functional/bin/python -m pytest plugin/tests -q
```

Настроить `.env` по [шаблону](../.env.example). Настоящий файл исключён из Git;
ключ не попадает в отчёты, shell-выражения не исполняются. LLM получает только
текст и описания известных поверхностей. В текстовом интерфейсе поддерживается
явная одиночная сила в Н с осевым направлением. Общие векторы задаются структурно;
моменты требуют отдельной модели нагрузки.

```bash
.venv-functional/bin/python experiments/check_functional_llm.py
.venv-functional/bin/python plugin/tools/plan_functional.py \
  experiments/functional_artifacts/beam.stl experiments/functional_artifacts/beam_task.txt \
  --spec experiments/functional_artifacts/beam_spec.json \
  --surfaces experiments/functional_artifacts/beam_surfaces.json --llm --mode classic --mesh-size 6 \
  --output /tmp/functional-decision.json
```

Роль `flat` сохраняется, но сама не удостоверяет плоскостность. LLM не может
перенести калибровку на другой материал, температуру или процесс.

## Доказательства и незакрытые проверки

Задание для проверки в установленном STE Slicer:
[ste_runtime_handoff.md](../experiments/ste_runtime_handoff.md).

T4/T10 на точном осевом стержне, квадратичный patch test, энергия/равновесие,
масштабирование нагрузок, направления материала; две модели с уточнением сетки;
семь примеров организаторов, компилятор, Double ML и живая LLM.

Отчёты: [численные метрики](../experiments/functional_results.json),
[LLM](../experiments/functional_llm_results.json),
[весь набор тестов](../experiments/functional_tests.xml).

Проверены встроенные runtime-контракты и исполнение модификаторов в штатном
движке на контролируемых сценах. Артефакты, ограничения и расхождение числа
слоёв: [runtime-отчёт](../experiments/ste_runtime_report.md).
Не проверены реальные отпечатки, Ra/плоскостность и 5D-траектории с оснасткой;
производственная аттестация не заявляется.

## Устойчивость выбранных параметров

В конце `plan_case` добавляется `robustness_analysis`. `noise_spec` задаёт
интервалы и источник, `robustness_limits` — допустимые интервалы метрик.
Считаются худшие зазор первого слоя, шаг слоёв, поток и чувствительность
линейной механики. Постоянная ошибка Z отделена от межслойного шума.
Условная переоценка допустимых кандидатов не меняет основной план автоматически.
При неизвестных допусках/модели отклика сохраняется `needs_calibration`.
[Формулы и протокол без утечек](../data/research/06_robust_process_validation.md).
