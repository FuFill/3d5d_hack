# Lenaz + исходное ядро: проверка интеграции

24.10.2026. В `main` сначала опубликован `c006fd3`, затем слита ветка Lenaz
(`3b6c9ce`). Исходные файлы `plugin/ste_planner` не изменялись.

Оболочка использует `plan_case` в современном worker, хранит решение под собственным
`plan_id`, применяет его через исходный `runtime_adapter.create_operation` в Qt,
затем выполняет `readback`. Алгоритмы материала, маршрута, ориентации, DoubleML,
прочности и шума не дублируются в оболочке. При сборке/установке сохраняется
точная копия исходного ядра; контрольные суммы — в [core_identity.json](core_identity.json).

Проверено:

- 186 тестов ядра прошли, один пропущен.
- 15 проверок оболочки прошли: для всех семи исходных STL/ТЗ решение отдельного
  worker совпадает с прямым вызовом ядра, включая статусы и объяснения;
  проверены отмена, устаревшее состояние проекта, SHA, допустимые локальные
  физические входы, запрет запоздалого Qt-callback и целостность сборки.
- Настоящий установленный STE 7.10.12/Python 3.5.7, отдельный профиль:
  HTTP/MCP → worker → Qt apply → отложенный readback → CuraEngine → G-code/3MF.
  Использован исходный пыльник организаторов, без изменения STL/ТЗ.
- Нативные настройки совпали с планом. Сцена, настройки и геометрия восстановлены
  Undo/Redo; вся операция занимает одну запись истории.
- Оболочка успешно выполнила пробный запрос в Timeweb/Qwen с ключом из локального `.env`.
  Ключ не возвращается через `/api/state`; точного значения ключа нет в сохранённых
  G-code, распакованном 3MF и readback.
- Оценка штатного движка: 86 618 с, 56,68 м / 156,8 г TPU. Это расчёт движка,
  а не измерение времени/массы реального отпечатка. Заголовок G-code содержит
  86 617 с и 56,6788 м; округлённое представление UI согласуется с ним.

Машиночитаемый результат и SHA нативных артефактов:
[native_report.json](native_report.json). Сами локальные сессии, токены, профили,
виртуальные окружения и `.env` не публикуются.

В процессе проверки исправлены только связи оболочки с API STE: штатные writers
G-code/3MF могут ждать Qt-callback, поэтому вызываются из фонового потока;
изменение служебного id контейнера после apply не считается изменением геометрии.
Контроль значений остаётся в исходном `readback`.

Сохранившиеся ограничения:

- Пыльник остаётся `needs_input`; успешная нарезка не подтверждает герметичность,
  долговечность, абсолютную прочность или физический оптимум.
- Исходная фигурка с тиражом шесть штук не помещается с резервами существующего
  адаптера. Первый нативный запуск честно отказал; количество и логика раскладки
  не менялись для обхода ограничения. Для полного прохода выбран исходный пыльник.
- 5D apply требует кинематики и проверки коллизий, `infeasible` блокируется.
  Изолированный исследовательский `analysis_only` не доступен чатовому агенту.
- Автоматический FE-поиск по повторным native-слайсам остаётся отдельным
  исследовательским API/CLI. Синтетические данные не используются как подтверждение
  качества реальной печати или как новые измерения для DML.
