# Вопросы получают ответ до предложения действий

Пример ошибки: пользователь спрашивает «почему так долго», а агент предлагает
изменить параметры и открывает карточку `ask_user` вместо объяснения.

## Причины

- Ошибка/таймаут классификатора включали режим `act` со всеми инструментами.
  Это поведение было прямо закреплено старым тестом `test_a_slow_router_falls_back_to_work`.
- Любое вложение STL/ТЗ автоматически включало `act`, независимо от текста вопроса.
- Тест ответа без инструментов подставлял правильную классификацию для сообщения
  «сделай прочнее» и не проверял, что список инструментов действительно отсутствует.

## Исправление

Явные вопросы и просьбы распознаются до сетевого классификатора. Например,
«почему так долго» не зависит от ответа сервиса классификации. Неоднозначные фразы
по-прежнему разбирает Qwen: предыдущие сообщения передаются как контекст, исходное
новое сообщение — отдельно от текста приложенного документа. Сбой классификации
не открывает доступ к инструментам.

В режиме ответа приложение читает состояние проекта, пресеты и готовую оценку
времени. Список инструментов не создаётся и не передаётся модели; в запросе
указано `tool_choice=none`. Новый слайсинг, настройка профиля и `ask_user` не вызываются.
Системная инструкция требует сначала объяснить причину, а нехватку сведений
обозначить словами, не заменяя ответ карточкой выбора.

| Сообщение | Поведение |
|---|---|
| «Почему так долго», включая вопрос с вложенным ТЗ | Объяснение, без действий и карточек |
| «Как уменьшить время?», «можно ли ускорить?» | Объяснение возможностей |
| «Ускорь печать», «можешь повернуть деталь?» | Инструменты доступны; обязательные уточнения сохранены |
| «Почему долго? Уменьши заполнение до 20%» | Смешанный запрос: объяснение и запрошенные действия |
| «Да» после предложения действия | Классификация по контексту; согласие может продолжить задачу |

Это консервативная маршрутизация, не универсальный языковой анализатор. Для
неоднозначных формулировок остаётся модельный классификатор; таблица — примеры
контракта, а не оценка точности на независимом корпусе.

## Проверка

[software_checks.json](software_checks.json): **113 тестов оболочки прошли**,
включая **45 новых регрессионных сценариев**. Проверяются вопросы без «?», старые
команды в истории, вложения с инструкциями, сбои и некорректные ответы классификатора,
вежливые просьбы и смешанные сообщения, а также настоящий JSON-запрос клиента.
Сравнения «как в прошлом проекте» и обороты «хочу что-то прочное» остаются
контекстными сообщениями, а обсуждение команды без кавычек не запускает её.
Импорт агента и шесть основных проверок маршрутизации дополнительно прошли
в настоящем Python 3.5.7 установленного STE Slicer.

[live_report.json](live_report.json): живой Timeweb/Qwen на общих тестовых фразах
и вымышленном снимке проекта. На «почему так долго» получено объяснение времени
по тонкому слою, стенкам и скорости; **карточек выбора — 0**. Запрос ответа отправлен
без tools с `tool_choice=none`. Сохранённые чаты, настоящие STL/ТЗ не передавались,
сцена STE не изменялась. Это проверка диалогового поведения, не физических свойств.

```powershell
python -m pytest plugin/shell_tests -q
python experiments/check_question_routing.py --output .runtime/question_routing_live.json
```

Второй вызов использует ключ из локального `.env`, требует сети и расходует квоту API.
После установки исправления полностью перезапустите STE Slicer: расширение Python
загружается при запуске процесса.
