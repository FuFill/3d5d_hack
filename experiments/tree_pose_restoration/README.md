# Восстановление положения нод 3D/5D

Проверено 25 октября 2026 года на установленном STE Slicer 7.10.12, Python 3.5,
с отдельным временным профилем. Рабочая сцена пользователя не менялась.

## Подтверждённая причина

`StateIO` сохранял только локальную матрицу. Декоратор `ZOffsetDecorator`,
`physics/automatic_drop_down` и `physics/automatic_push_free` оставались от предыдущего
состояния. Штатный `PlatformPhysics` после восстановления вычислял перемещение
`-bbox.bottom + z_offset` и повторно сдвигал деталь. `LockPosition` защищает в STE
только от расталкивания объектов, но не от опускания на стол.

На кубе 20 мм с унаследованным `ZOffset=-7` восстановление 3D-ноды с нижней гранью
на нуле давало нижнюю грань -7 мм. До исправления все девять проверенных переходов
нарушали сохранённые координаты: ошибка 7 мм в 3D и 3 мм в 5D.

Дополнительные дефекты: матрица применялась до явного переключения backend;
копии сопоставлялись по имени и пути в порядке обхода; параллельные HTTP-запросы
могли разойтись по порядку изменения сцены и выбранной ноды;
снимок делался до завершающей нарезки.

## Исправление

- Снимок содержит мировую/локальную матрицы, ID детали, `ZOffset` и настройки физики.
- При переходе/Undo/Redo временно блокируется физика и отменяется её таймер.
  Сначала восстанавливаются настройки и backend, затем параметры физики, смещение
  и полная матрица. Ошибка откатывается до помещения операции в историю Undo.
- В 5D выключается опускание на плоский стол. Отрицательная координата нижней грани
  в 5D сама по себе допустима: модель центрируется на оси вращения.
- Старые снимки читаются по локальной матрице, чужой `ZOffset` удаляется;
  однозначное сопоставление по имени/источнику остаётся запасным вариантом.
  Неоднозначные копии отклоняются до изменения сцены.
- Сервер сериализует переключение сцены/ветки чата, интерфейс ставит последний
  быстрый клик в очередь. Завершённая нода повторно считывается после нарезки.

Диагностика до/после находится локально в игнорируемых

`{"commands":[{"command":"tree_pose_check"},{"command":"quit"}]}` и выполните:

```powershell
.\.venv-functional\Scripts\python.exe plugin/tools/launch_ste_runtime.py --assistant --job .runtime/tree_pose_check/job.json --timeout 90
```

Проверка использует установленную реализацию физики STE, созданную явно в headless-
режиме. Печатный процесс и коллизии реального принтера здесь не проверялись.
Уже испорченные координаты, сохранённые старой версией в ноде, автоматически
реконструировать невозможно; такую ноду следует заново создать из исправленной позы.

## Сетка и состав деталей (дополнение)

Оставшаяся причина смещения: план, применённый к детали на столе, меняет не только
матрицу. В 5D `runtime_adapter.create_operation` заменяет центрированную сетку из
`STLReader` на исходный STL (без центрирования, с последовательными треугольниками),
а матрица плана рассчитана под новую сетку. Пакетный план добавляет копии, функциональный —
модификаторы-потомки. Нода дерева возвращала только матрицу: после возврата из 5D в
исходную ноду деталь съезжала на половину габарита исходного STL, копии и модификаторы
оставались на столе (а следующий план на месте отклонялся из-за них).

Исправление (`AIAssistant/agent/versions.py`):

- В снимке у детали есть ID сетки, её локальные габариты и ID родителя.
- Нода возвращает свою сетку (сетки сохранённых нод держатся в памяти сеанса). Если
  сетки уже нет (другой сеанс), но размеры совпадают, матрица сдвигается на разницу
  центров; у потомков — обратный сдвиг. Деталь с другой геометрией (перезагруженный
  изменённый STL) свою сетку сохраняет.
- Детали, известные дереву, но отсутствующие в ноде, снимаются со стола и
  возвращаются нодой, где они есть. Детали, добавленные пользователем позже, не
  трогаются. Всё это — тот же шаг Undo.
- Деталь, найденная по имени после перезапуска, получает ID из снимка.
- После перехода по дереву откат `revert_plan_changes` для старых планов недоступен.

Проверки: `plugin/shell_tests/test_tree_parts.py` (дерево из нескольких заранее
построенных веток — 5D на месте, партия, модификатор, вложенная ветка — и переходы
между ними, Undo/Redo, без сохранённых сеток); те же переходы на настоящих классах
Uranium (`SceneNode`, `MeshData`, `Matrix`); в `tree_pose_check.py` для настоящего STE
добавлена проверка `planned_mesh_and_batch_copies_follow_the_node`.
